# DocVM 技术文档

本文说明 DocVM（本地文档版本管理）使用的技术栈，以及核心功能的实现方式。

---

## 1. 产品定位

DocVM 是面向 Windows 本地使用的「SVN 风格」文档版本工具：

- **无需** Git / SVN 服务端或数据库
- 工作副本 + 增量提交 + 修订历史 + 回滚
- 浏览器 UI + 系统托盘驻留
- 可打包为单文件 exe 双击运行

数据全部落在软件同目录的 `.docvm/` 下，便于随盘拷贝与备份。

---

## 2. 技术栈

| 层次 | 技术 | 说明 |
|------|------|------|
| 语言 / 运行时 | Python 3.13 | 业务与打包主体 |
| HTTP 服务 | 标准库 `http.server` | 无 Flask / FastAPI，降低依赖与体积 |
| 版本引擎 | 自研 CAS（MD5 内容寻址） | 增量提交、去重存储 |
| Word 预览 | mammoth → HTML；回退 python-docx | 浏览器内预览 |
| Word→PDF | pywin32 + Word COM（可选） | 需本机安装 Microsoft Word |
| 托盘 | pystray + Pillow | 打开页面 / 退出 |
| 前端 | 单页 `index.html` + 原生 JS | 无 React/Vue 构建链 |
| 前端库 | marked / docx-preview / JSZip（static） | Markdown、部分 Office、压缩包辅助 |
| 打包 | PyInstaller onefile + windowed | `scripts/build.bat` + `.spec` |

## 3. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  main.py                                                │
│  · 单实例探测（HTTP 探活 127.0.0.1:404）                 │
│  · 启动 HTTP 线程 + 系统托盘                            │
└───────────────┬───────────────────────────┬─────────────┘
                │                           │
                ▼                           ▼
        ┌───────────────┐           ┌───────────────┐
        │  server.py    │  JSON API │  tray.py      │
        │  RequestHandler│◄────────►│  打开浏览器   │
        └───────┬───────┘           └───────────────┘
                │
                ▼
        ┌───────────────┐
        │  manager.py   │  工作副本门面（上传/树/预览/提交）
        └───────┬───────┘
                │
                ▼
        ┌───────────────┐
        │  repo.py      │  CAS 版本库（commit / rollback / cat / diff）
        └───────────────┘
                │
                ▼
        ┌───────────────────────────────────┐
        │  .docvm/                          │
        │  workspace / objects / revs / …   │
        └───────────────────────────────────┘

浏览器 ←→ http://127.0.0.1:404  ←→ templates/index.html
```

**分层职责：**

- `paths.py`：源码目录 vs PyInstaller `_MEIPASS` 资源路径
- `utils.py`：时间/大小格式化、隐藏目录等
- `preview.py`：docx/PDF 转换细节
- `repo.py`：版本语义（与 UI 无关）
- `manager.py`：把仓库能力包装成前端友好的结构（文件树、状态色等）
- `server.py`：HTTP 路由与静态/下载响应

## 4. 数据目录与存储模型

软件目录（exe 旁或项目根）下：

```
.docvm/
├── workspace/          # 工作副本：用户编辑、上传的真实文件
├── objects/ab/cdef…    # CAS 内容库：按 MD5 存 blob，相同内容只存一份
├── revs/{N}.json       # 修订元数据：树快照 + A/M/D + 说明
├── history.json        # 修订索引（列表展示）
├── ignore.txt          # 忽略规则（类似精简 gitignore）
└── backups/            # 本修订「变更文件」小 zip（便于外带核对）
```

### 4.1 内容寻址（CAS）

类 Git 对象库，简化为仅存文件 blob：

- 路径布局：`objects/{md5[0:2]}/{md5[2:]}`
- `ObjectStore.put_file`：已存在同 hash 则**零拷贝**；新增才复制进库
- 修订不保存整目录副本，只保存 `tree: { "相对路径": "md5" }`

因此：大文件未改时，后续提交几乎不再占用 objects 空间。

### 4.2 修订元数据（示意）

`revs/3.json` 大致包含：

```json
{
  "rev": 3,
  "message": "补充海关文档",
  "time": "2026-09-25 16:40:00",
  "storage": "cas",
  "tree": { "a.docx": "ab12…", "dir/b.md": "cd34…" },
  "changes": [
    { "path": "dir/b.md", "action": "A" },
    { "path": "a.docx", "action": "M" }
  ],
  "backup": "r3_….zip"
}
```

`history.json` 存轻量索引，供历史列表快速读取。

### 4.3 忽略规则

`IgnoreMatcher` 解析 `ignore.txt`：`*` / `?`、目录尾 `/`、注释 `#`。  
扫描工作区、提交、状态统计时跳过匹配项，避免工具包/安装包污染版本库。

## 5. 核心功能实现

### 5.1 启动与单实例

**文件：** `main.py`

1. 请求 `http://127.0.0.1:404/`  
   - 已响应 → 视为已运行：只 `webbrowser.open`，进程退出  
   - 未响应 → 绑定端口启动服务  
2. 端口被**非 DocVM**占用 → 弹窗错误退出  
3. HTTP 在守护线程 `serve_forever`；主线程跑 `pystray` 托盘阻塞  
4. 托盘「结束运行」→ `server.shutdown()` 收尾  

固定端口 `404`，便于书签与二次启动定位同一 URL。

### 5.2 文件状态（正常 / 修改 / 新增 / 删除）

**文件：** `repo.py` → `file_status` / 工作区扫描；`manager.py` → 着色与树节点

对比逻辑（相对 HEAD 树）：

| 状态 | 条件 |
|------|------|
| 新增 (A) | 工作区有，HEAD 无 |
| 修改 (M) | 两侧都有，MD5 不同 |
| 正常 | MD5 相同 |
| 删除 (D) | HEAD 有，工作区无（待提交变更里体现） |
| 忽略 | 命中 ignore |

前端文件树由 `/api/files` 返回嵌套结构；工具栏「提交」旁展示 pending 摘要，脏状态有脉冲提示。

### 5.3 增量提交（Commit）

**入口：** UI → `POST /api/save_version` → `VersionManager.save_version` → `DocvmRepository.commit`

步骤：

1. 扫描工作区，生成 `current_tree`（路径→MD5），应用 ignore  
2. 与 `head_tree` diff，得到 A/M/D  
3. 无变更则拒绝提交  
4. 仅对 **A/M** 调用 `store.put_file`（已有 hash 跳过）  
5. 写入 `revs/{n}.json`，更新 `history.json` 与内存 HEAD  
6. 可选：把本修订变更文件打成 `backups/` 下小 zip  

**不是**每次全量拷贝工作区；也**不是**全库 zip。

### 5.4 回滚（Rollback）

**入口：** `POST /api/rollback`

- CAS 修订（`storage == "cas"`）：按目标修订的 `tree`，从 `objects` `checkout` 覆盖工作区  
- 兼容旧版全量目录修订：若无 tree，走历史目录拷贝逻辑  

回滚会覆盖工作区未提交修改（UI 有确认）。

### 5.5 历史、检出单文件、差异

| 能力 | 实现要点 |
|------|----------|
| 历史列表 | 读 `history.json` + 各 rev 摘要 |
| 修订内文件下载 | `resolve_file_at` / `cat_file`：用 tree 里的 hash 定位 objects |
| 文本/HTML 差异 | `diff_file`：两端内容取出后做 difflib；docx 可抽 HTML 再比 |
| 修改前/后下载 | 前端带 `rev` 调 `/api/rev_file` 或 download API |

### 5.6 工作区文件操作

经 `VersionManager` 操作 `workspace/`：

- 上传（multipart / base64 JSON）、新建目录、重命名、移动、删除  
- 打开资源管理器（工作副本 / 变更包 / ignore / 某相对路径）  
- 路径均做相对工作区规范化，防止越出目录  

这些操作**不自动产生修订**；用户确认后再「提交」。

### 5.7 预览

**后端：** `preview.py` + `manager.preview_file` → `GET /api/preview`

| 类型 | 策略 |
|------|------|
| `.md` | 返回文本，前端 marked 渲染 |
| `.docx` | mammoth→HTML；失败则 python-docx 抽文本 |
| `.csv` / `.xlsx` / `.xls` | 前端 SheetJS 解析，多工作表 Tab 切换；可「用 Excel 打开」 |
| 图片 | 浏览器直接显示 / 或返回可访问 URL |
| PDF | 可内嵌；docx 可尝试 COM 转 PDF 缓存 |
| 其他 | `unsupported`，引导下载 |

**前端：** 预览区支持缩放、旋转、下载、全屏；工具条并入标题栏以节省高度。

### 5.8 前端交互要点

**文件：** `docvm/web/templates/index.html`（单文件 CSS+JS）

- 左右分栏 + 可拖拽 splitter  
- 工作区：标题「工作区」+ 搜索框（名称/路径过滤，自动展开祖先）  
- 多选：Ctrl / Shift；拖拽移动  
- 托盘场景下无「退出页面」按钮，退出走托盘菜单  
- 定时/聚焦时 `refreshQuiet` 刷新状态，尽量保留选中与展开  

图标采用 Lucide 风格 SVG 描边图标，避免系统字体缺字导致「碎图标」。

## 6. HTTP API 一览

基址：`http://127.0.0.1:404`

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/` | 主页面 HTML |
| GET | `/static/...` | 静态资源 |
| GET | `/api/workspace` | 工作区路径、HEAD、统计 |
| GET | `/api/files` | 文件树 + 状态 |
| GET | `/api/pending_changes` | 待提交变更 |
| GET | `/api/history` | 修订历史 |
| GET | `/api/preview?name=` | 预览数据 |
| GET | `/api/download` / `/api/raw` / `/api/pdf` / `/api/rev_file` | 下载与原文 |
| GET | `/api/diff` | 文件差异 |
| POST | `/api/upload` `/mkdir` `/rename` `/move` `/delete` | 工作区变更 |
| POST | `/api/save_version` | 提交 |
| POST | `/api/rollback` | 回滚 |
| POST | `/api/open_explorer` | 打开资源管理器 |
| POST | `/api/shutdown` | 结束服务（一般由托盘使用） |

请求/响应以 JSON 为主；文件下载用 `Content-Disposition`。

## 7. 打包与分发

1. `scripts/build.bat`  
   - 解析本机 Python（可手动输入路径）  
   - `pip install -r requirements.txt`（优先阿里云镜像，规避官方 PyPI SSL 问题）  
   - `PyInstaller --onefile --windowed` + `scripts/DocVersionManager.spec`  
2. 产物：`dist/DocVersionManager.exe`  
3. spec 将 `docvm/web/templates`、`static` 及 docx/lxml/mammoth/pywin32/pystray/Pillow 一并收集  
4. 运行时 `sys.frozen` 为真：数据写在 **exe 同目录** `.docvm/`，模板从 `_MEIPASS` 读取  

可选：`set SKIP_PIP=1` 跳过依赖安装直接打包。

## 8. 与 SVN / Git 的差异（设计取舍）

| 点 | DocVM | SVN / Git |
|----|--------|-----------|
| 协作 | 单机本地 | 远程仓库 / 多用户 |
| 存储 | MD5 CAS + 修订 JSON | Git 对象库 / SVN FSFS 等 |
| 工作流 | 编辑工作区 → 提交 | 类似，但无分支合并网络模型 |
| 忽略 | 简化 ignore.txt | svn:ignore / .gitignore |
| UI | 自带 Web | 依赖外部客户端 |

目标是「文档人员可双击使用的本地版本柜」，不是完整 DVCS。
